# Writing a guide

A guide connects a reader's task to a useful result. Start with its purpose,
then work through the draft, review, and maintenance decisions below.

## Define the scope

Decide which task the guide should help the reader complete. Keep unrelated tasks in separate documents so each page has a clear purpose.

## Identify the audience

Describe what the reader already knows and what they need to learn. Use that distinction to decide which terms need an introduction.

## Collect the sources

Gather the documents that explain the current behavior. Check each source before using it to describe an option or recommend a workflow.

## Prepare an outline

Arrange the material in the order the reader needs it. Put prerequisites before the steps that depend on them, and the result after the action.

## Write the first draft

Use short paragraphs and concrete examples. Explain the action and its immediate result together so the reader does not need to search elsewhere.

## Choose useful examples

An example should answer a real question. Keep the input and the visible result close together and remove details that do not explain the task.

### Compare source and result

Keep the example small enough that its input can be compared with the result at a glance.

## Check the terminology

Use one name for each concept throughout the guide. When a familiar word has a specific product meaning, explain that meaning when it first appears.

## Explain the prerequisites

List the tools and files that must exist before the reader begins. Distinguish required preparation from optional choices that can be made later.

## Describe the expected result

Tell the reader what a successful result looks like. Include a useful checkpoint before continuing to a task that depends on that result.

## Review the sequence

Follow the instructions from beginning to end. Check that each step has the information it needs and that no earlier task must be repeated unexpectedly.

## Verify the references

Open the linked material and check the destination headings. Prefer a specific explanation over a general page when the reader needs one exact answer.

## Review accessibility and alternative descriptions

Describe meaningful images in words and use descriptive link labels. Keep the heading hierarchy understandable without relying on visual size or color.

## Check the final examples

Compare the source with its rendered output. Keep names, values, and descriptions identical wherever both versions of an example are shown.

## Publish the guide

Build the site and check the completed pages before publishing. Keep the source changes together so the published result can be reproduced later.

## Gather reader feedback

Ask readers which step caused uncertainty and which result they expected. Use concrete feedback to improve the relevant paragraph instead of adding a general introduction.

## Maintain the guide

Review the guide when the product behavior changes. Update the affected example and reference together so the reader receives one consistent explanation.
